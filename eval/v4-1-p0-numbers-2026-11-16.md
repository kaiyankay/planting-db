**Finding.** Same engine, same rule, same seed, same snapshot — different inputs. The tree stands 0.5 m further east in Demo A, so
the tree keep-out removes a different three of the ten row positions, and the crowns that remain cover 0.12 m more of the edge.
Nothing was recomputed inconsistently; nothing was changed in the engine. What was wrong is that neither page named its case
next to the figure, so two cases read as one.

**What changed in V4.1 (Studio).**
- The Objective panel's "basis, rule, what is read" disclosure names the case: design name, design id, seed, and the preview
  fingerprint (`[data-case-id]`, `[data-read-fp]`), with the sentence "A figure on another page belongs to this result only when
  it names the same design and the same preview or version."
- `?script=v41` records `page.case_id` and `page.read_fp` beside every figure; `tools/ux_tests.py` P1 asserts they equal the
  engine's own.
- Note for About (not edited by the Studio fork): `demo-a`'s current version is a partial regeneration. With the V4.1 reading of
  versions (below) `T.refOf` now reports it as `derived: { how: 'partial regeneration' }`, so About can say so.

A side observation, not changed: Shape's basis sentence for the Screen band says "deep enough for a row and a staggered second
row", but the band it proposes is 0.9 m (small site) or 1.2 m, and the engine's row plan needs 1.33 m for salal alone and 2.21 m
for the salal + second-species mix. The sentence over-promises; `spatial.js` `screen_band_m` is an M53 parameter awaiting Kay.

## 2. Versions: generated, or derived

Reproduced before the fix:
- A **manual edit** (`E.directEdit`: move, delete, add a plant) spread the parent version into the new one, so the new version
  inherited the parent's `input_fp` and `preview_match`. Compose then read "same inputs as generated version N" and Trace read it
  as an untouched generated version — although its plants were no longer the engine's run.
- A **typed edit** (`E.previewEdit`) and a **partial regeneration** (`E.regenerateBeds`) carried no fingerprint and no mark; only
  the label told them apart. Neither produced a "What changed" note.

Fix (`design/js/model.js` `commitVersion`, `platform/js/trace.js` `refOf` / `refLine`, `design/js/app.js`):
- every committed version gets `objects_fp` (a hash of bed, species, role and position of its plant objects);
- a version with an `edit_event` is **derived**: `derived = { how: 'typed edit' | 'manual edit' | 'partial regeneration',
  from_version_id, from_objects_fp, base_version_id, base_input_fp }`; `input_fp` and `preview_match` are removed from it;
- `T.refOf` returns `fp: null` and `derived: {how, from_n, …}` for such a version, **also for files saved before V4.1** (read from
  `edit_event`; nothing in an old file is rewritten), and never reports `inputs_changed` from an inherited fingerprint;
- Compose's read line says "version N is a manual edit, so it is not this preview"; Grow's bar says "Version N of M · manual edit";
- one "What changed" note for all three (plant objects before → after per species, Screen figures, Screen checks, Ground Cover
  estimate), built from the two versions' own records; Undo/Redo clear it.

Tests: `tools/ux_tests.py` V4.1 · E1–E4 (generated, typed, manual, legacy file) at 1440 × 900 and 1280 × 800.

Not covered by a browser test: a **partial regeneration** made through the Grow "update the planting" card (the code path is the
same `commitEdit`, and `refOf` reads `geometry_update` as "partial regeneration"; the legacy `demo-a` file exercises the read side).
