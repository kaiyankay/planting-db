# Methods log — parameters and conventions decided while building the db

Every number or rule that is not a survey result and not a schema decision goes here: what it is, where it applies, why, who decided, when. Read with `HANDOFF.md` §3 (decisions) and `schema.json` rules R1–R10. When a parameter changes, add a new entry and mark the old one superseded; do not edit history.

Format: **M<n> · name** · value · applies to · rationale · decided by · date.

---

**M1 · cov_trees confidence baselines** · presence 0.95 · counts / local-area distribution 0.90 · cultivar label frequencies 0.85 · DBH distribution 0.80 · height-class distribution 0.75 · age cohort (trees with `date_planted`) 0.75 · established proxy (M2) 0.65 · applies to every claim with `source_id: cov_trees` · rationale: open municipal inventory is reliable on *presence* and *counts*; height is a banded class (M4) so lower; a proxy must rank below a direct measurement · decided by Kay (review of T1, 2026-10-29) with figures proposed by the coding agent · 2026-10-29.

**M2 · "established" proxy for trees without a planting date** · DBH ≥ 20 cm · applies to `local_mature_size` claims on the subset of trees that have no `date_planted`; the threshold is written into each claim's `value.threshold_dbh_cm` and `context`, and recorded in `sources.json → cov_trees.methods` · rationale: the 2026-10-26 snapshot carries no planting dates, so age cannot be derived; 20 cm DBH is a reasonable "past establishment" mark for a small tree like *Acer palmatum*. The wording is always *established (DBH ≥ 20 cm, proxy)*, never "mature". Trees **with** a planting date go to age-cohort claims (`time_to_intended_size`, 0.75) and are never mixed with the proxy subset · decided by Kay · 2026-10-29.

**M2a · minimum sample for an established-proxy claim** · n ≥ 20 trees in the subset; below that no proxy claim is emitted and the group's height-class claim says so in its `note` · applies to every group in M3 (on the 2026-10-26 snapshot this drops the proxy claim for 'Bloodgood' (3 trees) and 'Koto No Ito' (5)) · rationale: a median of three trees is an anecdote, not a distribution · proposed by the coding agent, **confirmed by Kay (D3, 2026-10-29)**.

**M3 · cultivar claim groups** · a cultivar label with n ≥ 50 records in the CoV inventory gets its own group of size claims, `context` = `cultivar:'Name'; CoV public trees, snapshot …`; labels below 50 stay inside the species-level claims and are listed by name and count in those claims' `note`; species-level claims are always kept, so one field shows "species overall" and "cultivar X" side by side; unlabelled trees (`cultivar_name` = NONE) form their own class `cultivar:(unrecorded)` and are never merged into any cultivar · applies to `local_mature_size` and, when dates exist, `time_to_intended_size` from `cov_trees` · rationale: *Acer palmatum* is in the prototype because of cultivar ambiguity; 407 Osakazuki records are a real sample; the (unrecorded) class is not the straight species · decided by Kay · 2026-10-29. Current groups (snapshot 2026-10-26): Osakazuki 407, Bloodgood 88, Koto No Ito 65, (unrecorded) 1,103.

**M4 · height_m is a class, not a measurement** · CoV `height_m` values cluster at 4.6 / 7.6 / 10.7 / 13.7 / 16.8 m (15 / 25 / 35 / 45 / 55 ft midpoints), ~97 % of *Acer palmatum* records · applies to every CoV height claim: `value.measure = "height class midpoint"`, text says "height class", confidence per M1 · rationale: quoting 7.6 m as a measured median would overstate precision · observed and decided by the coding agent, confirmed by Kay · 2026-10-29.

**M5 · value_kind back-fill rules (T3)** · `{min, max, unit}` ranges and count / distribution objects → `quantitative`; vocab enums, enum lists, booleans and object fields whose keys are enum-typed (e.g. `{fall_colour: true}`) → `categorical`; free notes and loosely structured prose objects (e.g. `{note: …}`, `{substitute_for: …, advantage: …}`) → `qualitative` · applies to the 18 claims that pre-date schema 0.2.0 and to every claim since · rationale: schema.json `claim.value_kind` · decided by the coding agent under HANDOFF T3 · 2026-10-29.

**M6 · refreshing cov_trees claims** · same snapshot, changed parameters → strip the previous `cov_trees` claims and regenerate (done once on 2026-10-29 when M2/M3 replaced the first run); new snapshot → run `cov_trees_to_claims.py --merge`: `merge_claims` appends the new claims (new snapshot date in `context`) and leaves the old ones as verified history under their own snapshot date · rationale: schema R1 (keep every sourced claim) and R10 (retire, don't delete) · decided by the coding agent, to confirm with Kay when the first new snapshot arrives · 2026-10-29.

**M7 · survey input location (T4)** · `inputs/survey/` holds the dated exports `responses-*.csv`, `survey-analysis-*.json`, `plant_candidates-*.json`; the ingester takes the newest set; idempotence key is `response_id` · decided by Kay · 2026-10-29.

**M8 · licence tiers and the T5 extraction protocol** · tier A open data (import values, e.g. cov_trees); tier B cite facts, never copy text (rhs, mobot, gpp, osu, iscbc, eflora, pojar); tier B-restrictive: terms forbid storing material, kept only for an absence-of-listing fact, Kay decides (aspca); tier C never import (kpu). Protocol per plant × source: (1) fetch and record the licence text and check date in `sources.json` before anything else; (2) read the plant page; (3) write structured values only into `inputs/t5/<plant>-<date>.json` with `source_url`, `accessed`, and `note` for every forced vocabulary mapping; (4) merge, all `status: unverified`; (5) `tools/review_list.py` → `review/<plant>-<date>.md`; (6) Kay ticks, `tools/verify_claims.py` sets verified and retires model placeholders (R10). Confidence = the source's `baseline_confidence`, lowered when a value was mapped loosely (e.g. 'moist but well-drained' → moist 0.75) · decided by Kay (process) and the coding agent (mapping discounts) · 2026-10-29.

**M9 · duplicate key for merge_claims** · a new claim is a duplicate of an existing one only when field, source_id, context AND value all match · rationale: cultivar claims from the same source can carry identical values under different contexts (RHS 'Osakazuki' and 'Bloodgood' are both 2.5–4 m); the first run without context dropped four of them · decided by the coding agent after the bug · 2026-10-29.

**M1a · height-based CoV confidence lowered (supersedes the height figures in M1)** · height-class distribution 0.70 · established proxy 0.60 · other M1 values unchanged · applies to every `cov_trees` claim whose value is derived from `height_m` · rationale: D4 — height_m is a class midpoint (15/25/35 ft), so every height-based claim says "height class midpoint" in text and value and is discounted a further 0.05; inferences about the data (the (unrecorded) class being older plantings; the 10.7 m median possibly including mislabelled maples) go in `note` prefixed "interpretation", never in value or text · decided by Kay · 2026-10-29.

**M10 · placeholder retirement (supersedes the trigger in R10's first wording)** · an unverified `model` placeholder is retired as soon as ANY claim with `source_type ≠ model` exists on the same field, verified or not; `retired_by` = the earliest such claim in file order · applies in `merge_claims` after every merge and in `verify_claims`; applied retroactively to the three *Acer palmatum* placeholders on 2026-10-29 · rationale: D6 — a sourced value, even unverified, beats a model guess; the placeholder stays visible as history · decided by Kay · 2026-10-29.

**M13 · iNaturalist aggregate layer** · place = iNaturalist place 27530 "Greater Vancouver, BC" (Metro Vancouver regional district) · filters verifiable=true, license=cc0,cc-by,cc-by-nc · stored: counts, research-grade count, year span, month histograms, Plant Phenology annotation histograms (flowering 13 / fruiting 14); never ids, users, coordinates or photos · confidence: presence/count 0.60, monthly observer-effort distribution 0.55, phenology 0.50 (all ≤ 0.6 per Kay) · thresholds: a phenology claim needs ≥ 20 annotated observations and a month counts when it holds ≥ 10 % of them; a monthly-effort claim needs ≥ 100 observations — **thresholds to confirm** · licence: terms page blocked by bot check on 2026-10-29; API description + GBIF dataset licence recorded instead; **tier B provisional, Kay to confirm by opening inaturalist.org/pages/terms** · decided by Kay (confidence cap, licences, no personal data) and the coding agent (place, thresholds) · 2026-10-29.

**M14 · native-status evidence goes to `ecological_value: ["native"]`, not a new field** · E-Flora BC and USDA PLANTS native-status facts are stored as gate-field claims `ecological_value = ["native"]` with the source's own wording in text; the entity's `origin_status` stays an entity attribute · rationale: the brief asks for origin_status claims from E-Flora/USDA, but `origin_status` is an entity field, not a tier field, and the gate enum already has `native`; this avoids a schema change · decided by the coding agent, **to confirm** · 2026-10-29.

**M15 · one source, two contexts, two claims** · when a source gives different values under different site conditions (OSU: salal under 2 ft in full sun on poor soil vs 4–10 ft in shade on good soil), each becomes its own claim with the condition in `context` · rationale: R1; this is exactly the "real mature size under local conditions" gap (survey c2) · decided by the coding agent under R1 · 2026-10-29.
